# Design — #42

## Problem

A role asked to specify or design PDF output has no team-side answer for how to produce one with this project's chosen library, `@cantoo/pdf-lib`: how its font embedding handles non-Latin text, how a page is set up through it, where it breaks lines and where it does not break pages, what its output actually is as a byte stream, or how a test asserts on what it produced. `technical-architect` can pay for a live sweep; `builder`, `reviewer` and `qa-engineer` would answer from memory — the one thing every playbook exists to forbid (`plugins/corporate/reference/stack-readiness.md:9-17`). Issue #42 closes that gap with the nineteenth stack playbook, `pdf-playbook`.

**This is a redo.** The playbook shipped at `4c0e8b0` and `78c7e16` against spec 1, which forbade naming any package; the spec was amended at `c6e3b33` and now requires the opposite. In scope: rewriting `## Stack` and the frontmatter `description` around `@cantoo/pdf-lib`, replacing the candidate-selection machinery with the settled choice and its rationale, re-anchoring every topic to the library's actual API, and demoting the maintenance check to a footnote. Out of scope, per the amended non-goals: treating library selection as an open decision; any format other than PDF; what a document should contain; storing or delivering the file.

`## Test suites` and `## Verification` are unchanged from the previous pass. The registration surfaces (T2) are unchanged and closed — see below.

## Approach

Amend the two shipped files in `plugins/corporate/skills/pdf-playbook/` — `SKILL.md` and `references/docs-map.md` — in place. Five rulings shape the redo; three of the previous seven are retired by the spec flip.

**1. The playbook becomes an ordinary playbook, and the old ruling 1 dies.** The previous design had to bend `docs/authoring.md:136` ("what the stack *is* … the packages to import") because requirement 2 then forbade naming a package, and borrowed `crypto-playbook`'s "the engine, not a binding" shape (`plugins/corporate/skills/crypto-playbook/SKILL.md:10-12`). That tension is gone. `docs/authoring.md:143-144` now describes this deliverable exactly: "name the current package in `## Stack` and the superseded one in `## Traps`". `## Stack` names `@cantoo/pdf-lib@2.11.0` (L1); `## Traps` names the unscoped `pdf-lib`, four years stale on the registry (L2). The `description` must also now name the package, per `docs/authoring.md:120-123` — which spec 1 forbade and spec 2 requires.

**2. The rationale is stated with numbers, and it is stated as settled.** Requirement 2 wants "lighter than a browser-automation approach such as Puppeteer" and "async API" as the justification for a decision already taken. Both are grounded: `@cantoo/pdf-lib` + `@cantoo/fontkit` measure 50 MB of `node_modules` and spawn no process, against Puppeteer's own documented "~282MB Linux" Chrome-for-Testing download (L19); the async surface is document-level, not per-mark — four `await`s in a whole document (L5). The four-candidate family table and the nine-criterion selection list are **deleted**, not softened: they are the machinery the amended non-goal forbids. The `choosing an approach` obligation row goes with them.

**3. ### Format facts F1–F18 — carried forward, condensed

Unchanged from `design.md@5372465`; verified by the reviewer at `docs/corporate/42/review.md:36-51`. Condensed here to the numbers and sources the file transcribes; argument dropped, fact kept. **F7 and F17 are superseded (ruling 3) and must not be transcribed.**

- **F1 — Authority.** ISO 32000-2:2020 is PDF 2.0; ISO 32000-1:2008 is PDF 1.7. Published at no cost by the PDF Association at `pdfa.org/sponsored-standards`; formalized errata per clause at `pdf-issues.pdfa.org/32000-2-2020/`.
- **F2 — Minimal valid byte stream.** Header `%PDF-n.m` as the very first bytes; a second-line comment of ≥4 bytes with codes ≥128; a body of `N 0 obj … endobj`; a cross-reference section; a trailer dictionary, `startxref`, `%%EOF`. Verified on a hand-assembled 669-byte file accepted by `pdfinfo` and `pdftotext`.
- **F3 — Trailer keys.** `/Size`, `/Root` required; `/ID` required from PDF 2.0 and whenever `/Encrypt` is present; `/Info` conditional; `/Encrypt`, `/Prev`, `/XRefStm` optional. Source: Arlington `tsv/latest/FileTrailer.tsv`.
- **F4 — Page object keys.** Required `/Type`, `/Parent`, `/Resources`, `/MediaBox`; `/Resources` and `/MediaBox` **inheritable** from the parent page-tree node; `/CropBox` optional, defaults to `@MediaBox`; `/Rotate` constrained to multiples of 90. Source: Arlington `tsv/latest/PageObject.tsv`; `/CropBox` default confirmed with `pdfinfo -box`.
- **F5 — Units and geometry.** Default user-space unit 1/72 inch, origin bottom-left; `/MediaBox [llx lly urx ury]`. Exact A4 = 595.276 × 841.89; US Letter = 612 × 792. **Nothing in the format expresses a margin.**
- **F6 — Simple vs composite fonts.** A simple font is single-byte, ≤256 addressable characters. Anything else needs Type 0: `/Subtype /Type0`, required `/BaseFont`, `/Encoding`, `/DescendantFonts`; `/Encoding` is a CMap, stream or predefined name (`Identity-H`, `Identity-V`, the CJK families). Source: Arlington `tsv/latest/FontType0.tsv`.
- **F7 — *Superseded by L9.* Do not transcribe.**
- **F8 — `/ToUnicode`.** An optional font-dictionary stream mapping codes to Unicode; absent it, extraction and search have no way back from glyph codes. Table 125a defines its stream dictionary. Sources: Arlington `FontType0.tsv`; `pdf-issues.pdfa.org/32000-2-2020/clause09.html`.
- **F9 — Standard 14 are Latin, and scoped to older processors.** Clause 9 errata restates the guarantee as written for "PDF 1.0 to PDF 1.7 files"; the set carries no non-Latin glyphs regardless. Source: `pdf-issues.pdfa.org/32000-2-2020/clause09.html`.
- **F10 — Line breaking is Unicode's.** UAX #14 rev. 55 (Unicode 17.0.0, 2025-09-05) produces "break opportunities", ~40 line-break classes, mandatory vs permissible; for ideographic scripts "lines can break anywhere, unless prohibited"; explicitly tailorable. Source: `unicode.org/reports/tr14/`.
- **F11 — Japanese specifics.** W3C JLReq (2020-08-11, from JIS X 4051): no inter-word spacing, so a break may fall between almost any two characters; kinsoku shori constrains it with 行頭禁則 (may not start a line) and 行末禁則 (may not end a line); line adjustment then fits the line. Source: `w3.org/TR/jlreq/`.
- **F12 — "It opens" is not "it is valid".** Replacing only the `startxref` offset with `999999` leaves `pdfinfo` and `pdftotext` both exiting 0 with correct output — poppler reconstructs the table by scanning.
- **F13 — `qpdf --check` and its limit.** Checks "structure as well as encryption, linearization, and encoding of stream data". Exit `0` none, `2` errors, `3` warnings only; `--warning-exit-0` collapses 3 to 0. qpdf's own caveat: a clean `--check` "may still have errors in stream data content". Source: `qpdf.readthedocs.io/en/stable/cli.html`.
- **F14 — poppler 24.02.0 tools.** `pdfinfo` (`-box`, `-isodates`, `-meta`); `pdftotext -enc UTF-8 f.pdf -` (`-layout`, `-raw`, `-nopgbrk`, `-f`/`-l`); `pdffonts` columns `name type encoding emb sub uni object ID`.
- **F15 — veraPDF is a separate tool.** Validates PDF/A and PDF/UA; `-f`/`--flavour` takes a two-character code (`-f 1b`), `-f 0` auto-detects. Source: `docs.verapdf.org/cli/validation/`.
- **F16 — Timestamps and `/ID` defeat golden bytes.** PDF 2.0 deprecates document-info entries except `CreationDate`/`ModDate`; `/ID` required from 2.0 (F3). Sources: `pdflib.com/pdf-knowledge-base/pdf-20/deprecated-features/`; Arlington `FileTrailer.tsv`. *Refined for this library by L16 — see there.*
- **F17 — *Superseded by L1–L3.* Do not transcribe.**
- **F18 — Content outside the page box is discarded; the format expresses no page flow.** *Normative:* ISO 32000-1:2008 §14.11.2.1, verbatim — the crop box "defines the region to which the contents of the page shall be clipped (cropped) when displayed or printed … The default value is the page's media box"; of the media box, "Content falling outside this boundary may safely be discarded without affecting the meaning of the PDF file"; and "The crop, bleed, trim, and art boxes shall not ordinarily extend beyond the boundaries of the media box. If they do, they are effectively reduced to their intersection with the media box." Clause numbering identical in ISO 32000-2, no formalized erratum against 14.11.2 (`pdf-issues.pdfa.org/32000-2-2020/clause14.html`). *Empirical (poppler 24.02.0, Ghostscript):* in-box and overflowing files render to byte-identical PNGs; `pdfinfo` and `pdftotext` both exit 0 with zero bytes to stderr and no trace of the out-of-box strings; changing only `/MediaBox` makes them extract; a baseline straddling the edge renders **differently** (glyph tops clipped) yet still extracts **nothing**, because extraction keys on the text origin. `qpdf` is absent from this machine — its behaviour here is inferred from F13's stated scope and must be stated as an inference. *Derivation:* a page object owns a content stream and nothing carries content to the next, so pagination belongs to whatever computes coordinates, exactly as a margin does. Detect positively: assert the page count **and** that the *last* expected string extracts.

### Library facts L1–L19 — new

Produced on this machine on 2026-09-14 (bun 1.3.14, poppler 24.02.0, Ghostscript) or fetched from the URL named. **A fact the file needs that is absent from F1–F18 or L1–L19 is a design defect to route back, never a licence to write it from memory.** The builder holds `Bash` and `WebFetch` and can re-run or re-fetch every one of these.

Four years stale on the registry, two on the repository, against a fork published three days before this design.
- **L3 — `latestRelease` is `null` on the fork.** The fork cuts no GitHub Releases, so the most obvious maintenance field returns `null` for a package published three days ago. The two signals that work are `pushedAt` (repository) and `bun info @cantoo/pdf-lib time.modified` or the `Published:` line (registry).
- **L4 — Install, footprint, exports.** `bun add @cantoo/pdf-lib` installed 6 packages in 734 ms; `bun add @cantoo/fontkit` a further 5 (`@cantoo/fontkit@2.0.12 | MIT | deps: 4 | versions: 9`). `du -sh`: `node_modules` 50 MB total — `@cantoo/pdf-lib` 32 MB, `@cantoo/fontkit` 13 MB. Named exports confirmed present at runtime: `PDFDocument`, `PDFPage`, `PDFFont`, `StandardFonts`, `PageSizes`, `rgb`, `grayscale`, `cmyk`, `degrees`, `TextAlignment`, `layoutMultilineText`. Subpath exports `./upng` and `./standard-fonts`. Everything in L5–L18 ran under Bun 1.3.14 with no shim.
- **L5 — The async surface is document-level, not per-mark.** Async, returning `Promise`: `PDFDocument.create()`, `PDFDocument.load()`, `doc.embedFont()`, `doc.embedPng/embedJpg/embedPdf/embedSvg()`, `doc.copyPages()`, `doc.save()`. Synchronous: `doc.addPage()`, `doc.registerFontkit()`, every `page.draw*()`, `doc.setCreationDate/setModificationDate/setTitle/setProducer/setCreator()`, `doc.getPageCount()`, `page.getSize()/getMediaBox()/getCropBox()`, `font.widthOfTextAtSize()`, `font.heightAtSize()`, `font.encodeText()`. Sources: the installed `cjs/api/PDFDocument.d.ts`, `cjs/api/PDFPage.d.ts`, `cjs/api/PDFFont.d.ts`; and `pdf-lib.js.org/docs/api/classes/pdfdocument`, which documents `create`, `load`, `embedFont` and `save` as returning `Promise` and `registerFontkit`, `addPage`, `setCreationDate`, `setModificationDate` as synchronous, and states of `registerFontkit`: "This must be done before custom fonts can be embedded."
- **L6 — Page setup is a tuple; there is no orientation option.** `doc.addPage()` with no argument → `{width: 595.28, height: 841.89}`. `PageSizes.A4 = [595.28, 841.89]`, `PageSizes.Letter = [612, 792]`, `PageSizes.Legal = [612, 1008]`. Landscape is the tuple reversed: `addPage([PageSizes.A4[1], PageSizes.A4[0]])` → `{width: 841.89, height: 595.28}`. `page.setMediaBox(0, 0, 300, 300)` → `getSize()` `{300, 300}` and `getCropBox()` `{x:0, y:0, width:300, height:300}` — the crop box follows the media box (F4, F18). Margins do not exist: `drawText` takes absolute `x`/`y`.
- **L7 — `PageSizes.A4` is rounded and is not the exact A4.** `PageSizes.A4[0]` is `595.28`; the exact value is 595.276 (F5). `pdfinfo` on generated output prints `Page size: 595.28 x 841.89 pts (A4)`. A test asserting `595.276` against a page made with `PageSizes.A4` fails.
- **L8 — `y` is the baseline.** On a 200 × 100 page, `drawText('Hg', {x: 20, y: 0, size: 48})` rendered with `gs -sDEVICE=pgmraw -r72` puts ink in rows 65–99 of 100, reaching the last row: the cap height sits above `y = 0` and the descender of `g` is clipped away at the page bottom, silently. `page.extractContents()` on a `drawText(..., {x: 72, y: 700})` returns `{kind: 'text', x: 72, y: 700, fontSize: 24, fontFamily: '…'}` — the value round-trips as the text origin.
- **L9 — A standard font silently substitutes `?`, and lies about the width. *Supersedes F7.*** `await doc.embedFont(StandardFonts.Helvetica)` then `page.drawText('日本語 OK', …)` raises **nothing**, and `save()` succeeds. `font.encodeText('日本語')` returns the hex string `<3F3F3F>` — three `?`. `font.widthOfTextAtSize('日本語', 24)` returns `40.032…`, the width of three question marks, so measurement is wrong too. `pdftotext -enc UTF-8` extracts `??? OK` and exits 0; `pdffonts` prints `Helvetica | Type 1 | WinAnsi | emb no | sub no | uni no`; `pdfinfo` exits 0, `Pages: 1`. Drawing with no `font:` option at all behaves identically — the library embeds Helvetica for you.
- **L10 — A custom font needs fontkit registered, and this one failure is loud.** `doc.embedFont(<TTF bytes>)` without `registerFontkit` throws `FontkitNotRegisteredError`: "Input to `PDFDocument.embedFont` was a custom font, but no `fontkit` instance was found. You must register a `fontkit` instance with `PDFDocument.registerFontkit(...)` before embedding custom fonts." `@cantoo/fontkit` is **not** a dependency of `@cantoo/pdf-lib` (L1) — it is a second, explicit install. The fork's README states `@cantoo/fontkit` is first-class and that upstream `fontkit` / `@pdf-lib/fontkit` remain compatible; only `@cantoo/fontkit` was executed here.
- **L11 — The correct non-Latin path, verified end to end.** `doc.registerFontkit(fk)`; `const jp = await doc.embedFont(ttfBytes, { subset: true })`; `page.drawText('日本語テキスト', { font: jp, x: 72, y: 700, size: 24 })`. Then `jp.encodeText('日本語')` → `<000100020003>` (glyph ids under Identity-H); `pdffonts` → `DroidSansFallback-9742 | CID TrueType | Identity-H | emb yes | sub no | uni yes`; `pdftotext -enc UTF-8` extracts `日本語テキスト` exactly, exit 0. The library builds the Type 0 font, the `Identity-H` encoding and the `/ToUnicode` map itself (F6, F8) — none of it is constructed by hand.
- **L12 — `subset: true` is 2 KB versus 2 MB, and `pdffonts` cannot see it.** Same 4,033,420-byte source TTF, same one-line document: `subset: true` → 2,486 bytes; `subset: false` → 2,321,699 bytes. `pdffonts` reports `sub no` in **both** cases — the library applies no `ABCDEF+` subset tag, which is what poppler keys on. The `sub` column is therefore not evidence for this library; assert on output size.
- **L13 — A missing glyph is `.notdef`, with a plausible width and no error.** `DroidSansFallbackFull.ttf` carries no Latin: `font.encodeText('Wrap')` returns `<0000000000000000>` — glyph id 0 four times — while `font.widthOfTextAtSize('Wrapping', 12)` returns `96`. `drawText` puts nothing on the page; `pdftotext` writes **zero bytes** and exits 0; `pdffonts` still reports `emb yes … uni yes`; `page.extractContents()[0].getText()` returns `" \n \n  \n"`. Every font-level assertion passes on a page with no readable text.
- **L14 — `maxWidth` splits on spaces, and nothing ever breaks a page.** `drawText`'s `maxWidth` wraps by splitting on `doc.defaultWordBreaks`, which is `[' ']` (installed `cjs/api/PDFDocument.js:132`); `cjs/utils/strings.js:103-128` accumulates whole tokens and pushes a line when `currWidth + width > maxWidth`, so a token wider than `maxWidth` is never split. Measured:
  1. **Latin works.** A 103-character English sentence at 12 pt with `maxWidth: 200` wrapped into three lines and extracted correctly.
  2. **Japanese silently runs off the page.** An 84-character Japanese string at 12 pt measures **1008 pt** wide; with `maxWidth: 200` it stayed one line, ran off a 595 pt page, and `pdftotext -layout` returned only the part inside the page box, ending mid-sentence at `…決まりません。日本`. Exit 0, no warning — `maxWidth` and F18 combining into one silent loss.
  3. **`wordBreaks: ['']` breaks per character, and applies no kinsoku shori.** The same string then wrapped inside `maxWidth`. But `あいうえおかきくけこ。さしすせそたちつてと、なにぬねの` at `maxWidth: 120` produced line 2 beginning with `。`, which JLReq's 行頭禁則 forbids (F11). Per-character breaking would also split Latin words, so a mixed-script paragraph has no single correct `wordBreaks` value.
  4. **No pagination at all.** One `drawText` of 120 numbered rows with `maxWidth: 451, lineHeight: 14` on one A4 page left `doc.getPageCount() === 1`; `pdfinfo` reported `Pages: 1`; extraction stopped at row 71 and `grep -c 'Row 120'` returned `0`. Every tool exited 0.
- **L15 — `save()` emits cross-reference streams by default; `trailer` and `xref` never appear.** Default `save()` on a created document returns a `Uint8Array` (1042 bytes for a one-line A4 document) beginning `%PDF-1.7\n` followed by the binary comment `%\x81\x81\x81\x81` (F2), and ending with an object whose dictionary is `<< /Size 9 /Root 2 0 R /Info 3 0 R /Filter /FlateDecode /Type /XRef /Length 44 /W [1 2 2] /Index [0 9] >>`, then `startxref`, then `%%EOF`. Measured on the bytes: the `trailer` keyword is **absent**, `\nxref\n` is **absent**, `/ObjStm` present, `/XRef` present, `/ID` **absent**. `save({ useObjectStreams: false })` emits the classic `xref` table and a `trailer` dictionary (`/Size 7 /Root 2 0 R /Info 3 0 R`). An in-process validity check that greps for `trailer` fails on this library's default output; check `%PDF-` at byte 0 and `%%EOF` at the tail instead.
- **L16 — Two `set*Date` calls buy byte reproducibility. *Refines F16.*** Two `save()` runs a second apart differ (`d6a1eb68…` vs `5fa6f12b…`). Calling `doc.setCreationDate(new Date(0))` and `doc.setModificationDate(new Date(0))` before saving makes them byte-identical (`6db11ff5…` twice) — those two calls alone suffice. It works because the library writes no `/ID` and targets PDF 1.7 (L15), so the timestamps are the only per-run bytes. `pdfinfo` also shows that `Creator` and `Producer` both default to the upstream project's name plus its repository URL, which ships in every document unless `setCreator`/`setProducer` overwrite them. **That string must be described, never quoted — quoting it puts a third URL in `SKILL.md`.**
- **L17 — `PDFDocument.load` succeeding is not a validity claim. *F12 at the library level.*** `load()` on a file whose `startxref` was overwritten with `999999` **succeeds** and reports 1 page. `load()` on the first 60 % of a valid file **succeeds and reports `getPageCount() === 0`** — no error at all. Only real garbage throws: `load(new TextEncoder().encode('not a pdf at all'))` → `MissingPDFHeaderError: Failed to parse PDF document (line:0 col:32 offset=16): No PDF header found`. "It loaded" is weaker than "it opened".
- **L18 — The network-free, CLI-free assertion path is the library itself.** `PDFDocument.load(bytes)` → `doc.getPageCount()`, `doc.getPage(i).getSize()`, `getMediaBox()`, `getCropBox()`, plus the fork's `page.extractContents()`, which returns typed assets; a text asset is `{ kind: 'text', getText(), x, y, fontSize, fontFamily }`. Verified round-trips against the three documents above: `"日本語テキスト\n"` (L11), `"??? OK\n"` (L9), `" \n \n  \n"` (L13). Structure, content, position and encoding can all be asserted in-process with no poppler, no qpdf and no network — which is what makes the `testing` obligation satisfiable under requirement 8. The CLIs remain the independent cross-check, not the requirement.
- **L19 — The weight comparison behind the choice.** Puppeteer's installation guide states that installing `puppeteer` obtains "a recent version of Chrome for Testing (~170MB macOS, ~282MB Linux, ~280MB Windows)" plus a `chrome-headless-shell` binary, cached in "`$HOME/.cache/puppeteer`", and that `puppeteer-core` "will not download Chrome when installed" (`pptr.dev/guides/installation`, fetched 2026-09-14). `bun info puppeteer` → `puppeteer@25.10.0 | Apache-2.0 | deps: 6 | versions: 1007`, depending on `puppeteer-core`, `chromium-bidi`, `@puppeteer/browsers`, `devtools-protocol`. Against that: 50 MB of `node_modules` and no subprocess (L4).

## Risks

- **Requirement 2 is now the inverse judgement and still only half-mechanical.** Acceptance catches a missing package name and a surviving family table; "reads as a rationale for a settled choice, not a comparison still open" is a human reading. The spec's own loop hint puts a person at that gate once, and the reviewer inherits it.
- **`SKILL.md`'s URL budget is one accidental paste from failing.** The library's own default `Producer` string embeds a repository URL (L16), the fork README's install line says `npm install`, and `pptr.dev` is a natural citation for L19. All three are forbidden in `SKILL.md`; two acceptance greps and an explicit step cover them, but a builder that quotes rather than describes will trip.
- **L1–L3 are the fastest-rotting facts in the set.** A version, a publish date and a `pushedAt` are true for days. Mitigated the way the spec asks: the file states the check as commands and states the reading as of 2026-09-14 rather than as a standing claim.
- **L9, L12, L13, L14 and L17 are observations of version 2.11.0, not contracts.** `<3F3F3F>`, `sub no` under `subset: true`, `getPageCount() === 0` on a truncated file — none is documented behaviour, and a minor release could change any of them. The file must present them as measured behaviour of a named version, not as API guarantees.
- **L12 contradicts the shipped `reviewing` obligation.** The current file's "reject a document whose fonts are not embedded" is fine, but any reader who reaches for `pdffonts`' `sub` column to check subsetting gets `sub no` on a correctly subsetted file. The trap must land, or the obligation becomes a false negative generator.
- **The file grows again.** It was already the longest playbook at 164 lines (`docs/corporate/42/review.md:87`). It gains the library's API surface and loses the candidate machinery; the band below is set as a cap on this file, and the "comparable playbooks occupy" justification the reviewer flagged is retired rather than re-stretched.
- **`qpdf` is still absent from this machine.** Its behaviour against an overflowing page remains an inference from F13's stated scope. The existing hedged wording must survive the redo unchanged.
