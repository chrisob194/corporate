# Angular Playbook

## Stack

Angular v22 is the current major and what a new workspace scaffolds on; for an
existing workspace, the major in its own `@angular/core` governs which rules
below apply.

- Builder: `@angular/build:application` is the default for applications
  generated by `ng new` — it compiles, bundles and minifies through esbuild,
  and can emit a client bundle, a Node server and prerendered routes
- Build output: base directory `dist/<project>/`. `outputPath` is a string
  (the base) or an object — `browser` defaults to `browser`, `server` to
  `server`, `media` to `media` inside the browser directory. A default build's
  client artifacts land in `dist/<project>/browser`, a server build in
  `dist/<project>/server`
- Static serving: the `browser` directory is the document root, and a routed
  SPA needs the server to return `index.html` for any path it has no file
  for. `<base href>`, set at runtime, is preferred for URL resolution; the
  build-time `--deploy-url` is the fallback
- Scaffolding baseline: `--package-manager bun`, `--ai-config claude-code`,
  `--strict` and standalone components on by default, zoneless already the
  default from v21+. Name `--ssr` explicitly — no default is documented, and
  the output contract above depends on which way it goes
- Tests: Vitest is the default runner via the `@angular/build:unit-test`
  builder, run through `ng test`

## Toolchain

| Job | Command |
|---|---|
| scaffold a workspace | `bunx @angular/cli@latest new <name> --package-manager bun --ai-config claude-code` |
| generate a component or service | `bunx ng generate component <name>` / `bunx ng generate service <name>` |
| dev server | `bunx ng serve` |
| production build | `bunx ng build` |
| unit tests | `bunx ng test` |
| update the workspace | `bunx ng update` |
| start the MCP server by hand | `bunx @angular/cli mcp` |

`mcp` is not among the documented `ng` commands, which is why that row keeps
the `@angular/cli mcp` spelling rather than `ng mcp`. Never `npm`, `npx`,
`yarn` or `pnpm` to reach `ng` — not in a shell, not in a `package.json`
script, not in CI, and not when translating a copied upstream snippet, which
prints `npx`. `ng update` takes no documented package arguments; assert none.

## Obligations by activity

| Activity | Obligation |
|---|---|
| any | `angular.dev` is the authority for Angular itself, with exact pages resolved through `angular.dev/llms.txt`; a fact it covers is read there, never asserted from memory |
| any | `angular.dev/assets/context/best-practices.md` is the authority for current practice; no other source substitutes for either page, and where the tree is unreachable, the MCP server's own documentation and best-practice tools are the fallback where present, otherwise the installed `@angular/*` packages' type definitions |
| choosing an approach | name whether the app is SSR at scaffold time — the output and serving contract above follows from it. Learn the real workspace layout before proposing structure |
| implementing | signals, standalone, native control flow, `inject()`, the `host` object, no `CommonModule` — the baseline in `## Traps` below. Where the Angular CLI MCP server is in the session, its tooling is this team's path for scaffolding help, best-practice lookup and build or dev-server verification, with the `## Toolchain` commands the fallback when it is absent |
| testing | Vitest through `ng test` — not a separately wired runner |
| reviewing | reject the superseded patterns in `## Traps` |

Individual MCP tools named only where both the upstream docs and a running
server agree on the name: `list_projects`, `get_best_practices`,
`search_documentation`, `run_target`, `onpush_zoneless_migration`. The
dev-server tools are referred to by task, never by a pinned name — the two
sources spell them differently.

## Traps

- `*ngIf` / `*ngFor` / `*ngSwitch` for `@if` / `@for` / `@switch` — the
  structural-directive forms are superseded, not merely alternative syntax
- NgModules for standalone — and the related error of writing
  `standalone: true` explicitly, which is the default already and reads as a
  leftover from a pre-v20 project
- setting `ChangeDetectionStrategy.OnPush` explicitly — the v22 default, so a
  component that names it is either stale or on an older major
- `@HostBinding` / `@HostListener` for the `host` object
- `ngClass` / `ngStyle` for `class` / `style` bindings
- importing `CommonModule` rather than the specific directives and pipes a
  template actually uses
- constructor injection for `inject()`
- RxJS-heavy state for signals, and `mutate` on a signal in place of
  `update` / `set`
- **deploying `dist/<project>` instead of `dist/<project>/browser`.** The base
  directory also holds `server` and `media` when SSR is on — none of that is
  what a static host should serve
- **a static host with no `index.html` fallback.** The root route passes and
  every deep link 404s, because a client-side router never gets a chance to
  handle the path
- assuming Karma is still the runner — it is still supported, but Vitest is
  what a new workspace scaffolds
- `zone.js` left in `polyfills` on a zoneless app
- `npx @angular/cli` copied verbatim from upstream docs — every upstream
  snippet prints `npx`, and the translated command is what belongs in a file
